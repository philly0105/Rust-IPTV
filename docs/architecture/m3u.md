# M3U

Code: `crates/iptv-core/src/m3u/`. Tests: `crates/iptv-core/tests/m3u_parse.rs`, `m3u_import.rs`, `m3u_series.rs` (series grouping, `m3u.seriesDetail`, `m3u.streamUrl`, the watched mark, state, locks and hidden flags of episodes imported as movies (after a token rotation too), the startup re-import of older catalogs, the stream URL of M3U movies in `catalog.item`), `l1_m3u_import.rs` (remap, empty playlist, `IMPORT_VERSION`, `connecting` and `unchanged` progress), `m3u_disk_text.rs`, `m3u_channel_fields.rs`, `m3u_perf.rs` (check 4), with helpers in `m3u_support.rs`.

## Layout

| File | Role |
| --- | --- |
| `parser.rs` | `M3uReader<R: BufRead>`, a streaming iterator of `M3uEntry`, plus `M3uHeader`, `ParseStats` and `parse_str`. |
| `importer.rs` | `M3uImporter` (the m3u `Importer`), `import_source`, `RowBuilder`, `classify`, id helpers. |
| `series.rs` | Episode detection, `SeriesGrouper`, the stored episode list, `m3u.seriesDetail` / `m3u.streamUrl`, and the move of state saved on episodes imported as movies. |
| `rpc.rs` | `m3u.raw`, `m3u.parsePreview`, `m3u.seriesDetail` and `m3u.streamUrl`. |
| `mod.rs` | `init`, which registers the importer and removes `tmp/m3u-*.part` files left by a crash. |

## Parser

The reader works on any `BufRead` and holds one line at a time. Lines are capped at 64 KB; a longer URL line is skipped. Edge cases handled, most taken from the old app's `iptv-playlist-parser` and `m3u-utils`:

- UTF-8 BOM, LF, CRLF and CR-only line endings (a lone `\r` ends a line; a CRLF split across reads is one break), and a case-insensitive `#EXTM3U`.
- Header EPG URLs from `url-tvg`, `x-tvg-url` and `tvg-url`. Comma-separated lists are split and de-duplicated. Repeated `#EXTM3U` lines in concatenated playlists are merged.
- Attribute values in double or single quotes, which may contain commas, and unquoted values. The name starts after the first comma outside quotes.
- `#EXTINF:0`, `-1` and missing durations.
- An empty name falls back to `tvg-name`, then the last URL path segment, then the URL.
- `#EXTGRP` overrides `group-title`. `#EXTVLCOPT:http-user-agent` and `http-referrer` set request headers. `#KODIPROP` lines before `#EXTINF` attach to that entry, and lines between `#EXTINF` and its URL attach to the same entry.
- `url|User-Agent=..&Referer=..` suffixes are cut off the URL and become headers.
- A bare `scheme://` line without `#EXTINF` becomes an entry.
- A dangling `#EXTINF` (no URL before the next one), junk text and overlong URLs are skipped and counted in `ParseStats.skipped`. They never fail the import.
- Duplicate URLs are kept as separate entries.

## Import

`import_source(state, source)`:

1. Get the bytes and their sha256. Every stored sha (`playlist_sha`, `playlist_hasher`) is seeded with `tsrust-m3u-import-v{IMPORT_VERSION}`, so bumping `IMPORT_VERSION` (4 now: 3 grouped series; 4 changed the series key, the show of a title that starts with its marker, and the ids of an episode's versions) re-imports every unchanged playlist (URL, file and pasted text) once on its next refresh and applies parser or classifier fixes; bump it whenever a change alters the rows an import writes. A sha stored by an older importer never matches. Each import also records the version that wrote the catalog in `app_state` (`m3u_import_version:<id>`, written in the import transaction, and by an unchanged refresh, whose sha or 304 validators carry the version; dropped by `sources.remove`). The startup pass (`sources::schedule::startup`, see sources.md) re-imports once every M3U source with a stored playlist and a good refresh whose recorded version is lower or missing (`importer::stale_imports`), whatever its `autoRefresh` and age. Pasted and uploaded text re-imports from the stored text, without the network, so those sources get new import rules too. A failed or cancelled attempt is tried again at the next launch.
   - `text`: read `m3u_raw.raw`.
   - `file` and `file://` URLs: hashed in a streaming pass.
   - `http(s)` URLs: `fetch_conditional` sends the request with the source's headers through `http::apply_source_headers` and retries network errors and 5xx (3 attempts), but not a timeout: a head that does not arrive within `PLAYLIST_HEADER_TIMEOUT` (120 s) comes from a slow generator and fails at once (the request goes through `http::guarded_long_client`, whose 150 s read timeout does not cut that wait short: reqwest's read timeout also runs while the head is awaited, and the normal clients' 60 s one would), and neither does a body that stalls after the head: body chunks are read through `http::next_body_chunk` with `BODY_IDLE_TIMEOUT` (20 s), and the stall fails once with a Timeout naming the host. A body that averages under 1 KB/s over a 60 s window (`m3u/body.rs` `MinRate`) fails the same way, so a drip-fed server cannot hold the import open. `sources.remove`, and a `sources.update` that changes the source's settings, cancel the running import through the per-source token `sources::import_cancel` (no waiting behind the import lock), and the cancelled download deletes its temp file. A non-2xx status names the host and adds a next step (`playlist_status_error`). In the first import of `sources.add` (`http::interactive`, see sources.md) the connection gets 3 s instead of 10 s, and a connect timeout ends the download at once, without retries, with "Could not reach <host>. The server did not answer. Check the address and port, and that the server is online, then try again." It streams `bytes_stream()` into `data_dir/tmp/m3u-<id>-<uuid>.part` and hashes as it writes. The temp file is not fsynced while it downloads: it is parsed at once, and most bodies are stored inline or dropped. Only a body kept on disk as `playlists/<id>.m3u` is synced (`sync_data`) before the rename, because backups export that copy and an unchanged refresh never rewrites it. Conditional requests (ST-3): after an import or an unchanged refresh of a downloaded body, its `ETag` and `Last-Modified` are stored in `app_state` (`m3u_validators:<id>`, with the URL, the body's sha256 and `IMPORT_VERSION`; dropped when the server sends neither, and by `sources.remove`). A refresh of a source imported before sends them as `If-None-Match` / `If-Modified-Since` while they still describe the imported body (same URL, sha equal to `m3u_raw.sha256`, same `IMPORT_VERSION`), and a 304 keeps the catalog like an unchanged sha, without a download. A drop guard deletes the temp file. URLs are redacted in logs.
2. If the sha256 matches `m3u_raw.sha256` and the source has been imported before, only `fetched_at` is updated and the cached counts are returned with `ImportSummary.unchanged` set. Hidden categories, favorites and positions are untouched. `run_import` then emits `import.progress {phase: "done", message: "unchanged"}` and no `sources.changed` (see sources.md).
3. Otherwise `write_catalog` runs on the blocking pool in one IMMEDIATE transaction:
   - A `CatalogWriter` covers live, radio, movie and series.
   - The parser streams entries through `RowBuilder` into the writer. `import.progress {phase: "parsing"}` is emitted every 2,000 items, at most one per 250 ms (`sources::ProgressGate`, the gate the download phase uses), and the final count goes out when the gate held it back. Parsing and the write wait for the import save slot (`sources::save_slot`, see sources.md), so only one import parses and saves at a time. Series episodes are held back and written as one row per show once the playlist ends (see Series).
   - Around that, `saving` names its step (see sources.md): `replacing` before the writer deletes the previous rows, when the source had rows (`Remapper::before` counted them), and `indexing` with `done` and `total` set to the entries written, once every entry is in and the ids are remapped, before the writer rebuilds the indexes, the search index and the counts.
   - A file with no `#EXTM3U` and no entries fails with `Invalid`.
   - A playlist with no entries (a bare `#EXTM3U`, which panels answer during maintenance or after an account lapses) never wipes the catalog: the import fails with `Invalid` before the commit and the previous rows stay ("The playlist came back empty; kept the previous channels"; on a first import, "The playlist is empty").
   - Item ids that changed on re-import are remapped so user state stays attached (`m3u/remap.rs`). An id hashes the stream URL and name, so a provider that rotates a token in its URLs gives every row a new id. Inside the same transaction, every table that stores item ids (favorites, recent, positions, downloads, reminders, recordings, My List, channel edits, custom lists, recording rules, watch log, EPG mappings, per-channel guide shifts, parental locks) is rewritten from a vanished id to the new id with the same identity: `tvg-id` + name when the entry has a `tvg-id`, otherwise name + group, same content type. Only unique matches move; anything ambiguous is left alone. The remapper keeps strings only for the referenced ids and their identities; every other old row adds a hash of its id and a count under a hash of its identity, and a new row is kept only when its identity is a referenced one (a hash collision can only make a match look ambiguous).
   - `m3u_raw` is upserted with the sha256 and, for playlists up to `RAW_INLINE_MAX` (8 MB), the text. The limit applies to the decoded text (`read_text_lossy`), because a small gzip file can unpack far past it; a file already over the limit on disk is not read just to measure it, and neither is one whose decoded size, counted by the parser (`ParseStats.bytes`), is over it. Larger file / URL playlists, a gzip that unpacks past the limit included, store `raw = ''` and keep a copy at `data_dir/playlists/<id>.m3u` (the downloaded temp file is renamed there; a user file is copied), written after the commit, so an import never holds the whole file in memory. `stored_text` returns the inline text or the copy; `m3u.raw` uses it. A text-origin source whose `raw` is `''` and that has a cached copy (a large pasted or restored playlist, see `place_raw_text`) is parsed from the copy. A text-origin source that was imported before and has a stored sha256 is unchanged without reading its text: pasted text only changes through `sources.add` or a restore, and both store its sha or `''`. `m3u::init` first moves the staged text of every committed `sources.update` into place (`importer::finish_all_staged`, see sources.md), then deletes `playlists/*.m3u` files with no `sources` row (a `<id>.update.m3u` of an update that never committed included; one whose move failed again stays for the next import) and leftover `.m3u.part` writes.
   - `epg_json.detectedUrls` is set from the header; manual and disabled lists are left alone.
   - Any error rolls everything back, so a failed refresh keeps the previous catalog.

The whole remote body is never held in a `String` while downloading or parsing.

### Row mapping

- `item_id` is 16 hex chars of sha256(url + `\n` + name). An exact duplicate entry (same URL and name) gets the hash of `url\nname\n#n`, with n starting at 2, so every copy survives.
- `category_id` is 16 hex chars of sha256(group). Entries without a group use "Uncategorized". Categories keep first-seen order per type.
- Content type (`classify`): `radio="true"` is radio. An Xtream VOD URL (a `/movie/` or `/series/` path, the shape of an Xtream `get.php?type=m3u_plus` list) is a movie whatever its group, and so is an mkv, avi, m4v or mov URL. An mp4 URL is a movie only in a group whose name contains movie, vod or film (looping live channels use mp4 too). Everything else is live. A movie that is a series episode becomes part of a series row instead (see Series).
- `number` is `tvg-chno` when present, else one running counter shared by live and radio, so a radio number never repeats a live one (movies get none). `position` is the order within the playlist.
- `logo_url` comes from `tvg-logo`, `epg_channel_id` from `tvg-id`, and `archive_hours` from `catchup-days` × 24 when the catch-up type is usable (see catalog.md). `catchup` is lowercased; a `catchup-source` without `catchup` means `default`.
- Movies get `poster_url`, `title_base`, `year` and `container_extension`.
- `extra_json` holds `tvgName`, `tvgShift`, `catchup {type, days, source}`, `headers {userAgent, referrer, origin}`, `vlcOpts` and `kodiProps` when present.
- ClearKey DRM: a channel whose `kodiProps` say `inputstream.adaptive.license_type=clearkey` (or `org.w3.clearkey`) with a `license_key`, or `inputstream.adaptive.drm_legacy=org.w3.clearkey|<licence>`, carries the licence as written in `Channel.clearKey` (`ItemRow::clear_key`). The UI parses it (`src/features/player/clearKey.ts`): `kid:key` pairs in hex or base64url, several separated by commas, a JSON map `{"<kid>":"<key>"}`, a JWK set `{"keys":[{"kid","k"}]}`, or a licence server URL (Kodi's `url|headers|...` keeps the URL). The player source gets `drm: {clearKeys}` or `drm: {licenseServer}`, which shaka takes as `drm.clearKeys` or `drm.servers['org.w3.clearkey']` for DASH. Neither mpv nor VLC takes ClearKey keys, so such a source always plays in the built-in player (`modeForSettings`). Other DRM systems (Widevine, PlayReady) are not supported. M3U catch-up of a ClearKey channel carries the same keys.

## Series

`RowBuilder::push` asks `series::detect` about every entry `classify` calls a movie. An entry is an episode when its URL has a `/series/` path (Xtream `m3u_plus`), or when its title has an episode marker: `S01E02`, `S1 E2`, `s01.e02`, `S01-E02`, `S01 Ep 02`, `1x02` (two or three episode digits, so `4x4` stays a title) or `Season 1 Episode 2`. Live channels and radio are never episodes. A `/series/` entry without a marker is season 1, numbered in playlist order.

- The show is the title before the marker, without trailing separators (`EN - Dark (2017) S01 E02 - Lies` is `EN - Dark (2017)`, episode title `Lies`; with nothing after the marker the episode title is the whole name). A title that starts with the marker takes the show from `tvg-name` (the part before its own marker when it has one, else the whole cleaned value; a blank one, or one that only repeats the episode title, does not count), then the group.
- Episodes group by group (`group-title`) plus `title_base` of the show, normalized (case, spaces), plus its year, so `EN - Dark (2017)` and `Dark (2017)` in one group are one show and the same show in a `4K` group is another. `title_base` drops every bracketed tag, so the key adds back the country tags of the show (`catalog::country_tags`: `[US]`, `[UK]`, `[GB]`, `[AU]`, `[CA]`, `[NZ]`, `[IE]` and three-letter `USA`, `AUS`, anywhere but at the start, where a tag is a language prefix) as `(us)`: `The Office [US]` and `The Office [UK]` are two shows, and `The Office [US]` and `The Office (US)` one. Other codes (`[DE]`, `[FR]`) mark a dub's language as often as a country and still merge. The series row keeps the first spelling as its title, the first episode logo as its poster, the group as its category and the playlist position of its first episode.
- The series id is 16 hex chars of sha256(`series\n` + group id + normalized title, country tags included, + year), and an episode id hashes the series id with `S<n>E<n>` (or the entry name when there is no marker). Neither includes the URL, so a provider that rotates tokens keeps positions, watched marks and downloads on their episodes. Versions of one episode (`EN - Dark S01E02` and `DE - Dark S01E02`) are told apart by entry name, not playlist order (`series::episode_ids`): in name order the first has the plain hash, the others hash their name with it, and exact repeats of a name add `#2`, `#3` in playlist order. A playlist that reorders the versions keeps every id, and so does one that drops a version other than the first by name; when the first leaves, the next one takes the plain hash. A lone episode keeps the id it had before. Every entry still takes its movie id in the builder, so the duplicate suffixes, and the ids, of the movies around it are what they were before grouping.
- The episodes are stored in the series row's `extra.episodes` (`StoredEpisode`: `id`, `season`, `episode`, `title`, `url`, and `posterUrl` when it differs from the series poster, `containerExtension`, `durationSeconds` from `#EXTINF`, `headers` from `#EXTVLCOPT` or `url|User-Agent=`). Grid pages read the row like any series; `catalog.series`, search and the counts see one row per show. A grouped group is a series category and no longer a movie category. Hidden flags and parental locks are stored per content type, so the import that first writes a series category gives it the hidden flag and the parental category lock of the movie category with the same group id (`series::GroupCarry`, read before the writer deletes the categories). A lock on a movie group that held episodes therefore keeps covering those shows in Hide and Ask mode. The movie lock stays. Later imports leave an existing series category alone, so a series group the user has unhidden or unlocked since stays that way.
- `m3u.seriesDetail {ref}` returns a `SeriesDetail` from the row: seasons in number order, episodes by number (playlist order on a tie), no cast, plot or trailer. `m3u.streamUrl {ref, episodeId}` returns the episode's `PlayerSource`: its URL, kind by extension (`m3u8`/`m3u` hls, `mpd` dash, else direct), and the playlist's headers with the entry's own over them, field by field. Both refuse a title parental hide mode hides, a ref that is not a series (`invalid`), a missing row or episode (`not_found`), and `m3u.streamUrl` without an episode (`invalid`). The watched sync (`watched::sync_series_mark`) reads the same list, so finishing or marking the last episode marks the series.
- State saved on episodes that imports before grouping stored as movies moves to the series in the import transaction (`adopt_movie_state`). The importer reads which movie ids the user tables mention before it writes (`referenced_movie_ids`), and every episode whose movie id is among them moves: positions and watched marks become episode rows of the series, favorites, My List and parental item locks point at the series (with the series title in their snapshot), downloads at the episode (title and `S01E02 · title` subtitle), and the watch log's seconds add up under the series. When the series already has a row (two favorited episodes of one show), it stays and the movie row is deleted; a download that would collide stays as it was. History keeps one series row with the newest `viewedAt` of its episodes and that view's snapshot, whichever episode comes first in the playlist. When every episode the series row lists ends up watched, the import also sets the series' own watched mark, as `watched::sync_series_mark` does after an episode write. An episode whose URL changed since that import wrote its movie row (a token rotation in between) has another movie id now, so it is matched by identity instead (`remap::identity`, `tvg-id` + name or name + group, read from the old movie rows before the writer deletes them, `Remapper::movie_identities`): its state moves when exactly one old referenced row and exactly one movie entry of the playlist have that identity, and no entry still has the old row's id. `IMPORT_VERSION` 3 and the startup re-import of older catalogs make every M3U source re-import once, which runs it; state that a version 3 import already left behind with the old movie rows deleted cannot be matched any more.

The UI asks `m3u.seriesDetail` for an M3U series detail (`detailCommand` in `src/features/vod/hooks/queries.ts`; movies keep `catalog.item`), and `m3u.streamUrl` to play, queue (`episodeQueue.ts`) and download (`usePlayback.ts`) an M3U episode. The rail shows Series for an M3U source whose `seriesCount` is above 0.

## Movies

An M3U movie plays and downloads from the playlist's own link. `catalog.item` returns it on the `VodItem` of an M3U source: `url`, and `headers` when the entry has its own (`#EXTVLCOPT`, `url|User-Agent=`). The player (`resolveSource` in `src/features/player/store.ts`) and downloads (`streamSource` in `src/features/vod/hooks/usePlayback.ts`) merge the playlist's headers under them, as for channels. Only `catalog.item` and `catalog.items` (the same lookup for each of its refs) set these fields, after the parental hide-mode check, and only when the source's kind is `m3u` (`catalog::is_m3u_source`, `NamedRow::into_m3u_vod`). Movie lists, search and `sameTitle` stay without links, and an Xtream or Stalker movie never gets one: their links carry the account and come from `xtream.streamUrl` and `stalker.streamUrl` at play time.

## Performance (check 4)

`tests/m3u_perf.rs` imports a generated 50,000-channel file through `sources.add`. On this machine a release build takes about 1.1 s with a peak RSS delta of about 31 MB; the limits are 3 s and 200 MB. The fast path relies on the FTS trigger suspension and `temp_store=MEMORY` described in catalog.md.

## Catch-up override

`M3uSourceConfig.catchup {type, template?, days?}` overrides every live channel's catch-up attributes; the source edit dialog sets it ("Catch-up override"). `type` is `default`, `append`, `shift`, `flussonic`, `xc` or `none` (catch-up off). `template` (at most 2048 characters, no control characters) replaces `catchup-source` and `days` (1..366) replaces `catchup-days`. `sources.add`/`sources.update` validate it (`catchup::m3u::validate_override`). It is applied when channel rows are read (`catchup::m3u::apply_overrides` on every catalog read path and on `live.alternates`), so changing it never needs a re-import, and an edit that changes only the override does not cancel a running refresh. Backups export and import it with the source.

The archive URL builder exists twice, in `catchup/m3u.rs` and `src/features/live/lib/catchup.ts`. Both are tested against `fixtures/catchup-url-cases.json`; override cases list the `effective` channel attributes after the override.

## rpc

- `m3u.raw {sourceId}` returns `{text, sha256, fetchedAt}`, or NotFound before the first successful fetch.
- `m3u.parsePreview {text}` parses the first 2 MB, cut at a line boundary, and returns `{channelCount, groups (max 500), epgUrls}`.
- `m3u.seriesDetail {ref}` and `m3u.streamUrl {ref, episodeId}`: see Series.

## Known limits

- Playlists over 8 MB are not copied into `m3u_raw.raw`; readers other than `m3u.raw` (backup export, backup fingerprint) must read through `m3u::stored_text`. An 82 MB, 480k-channel file imports with a peak RSS delta of about 50 MB (`m3u_perf::import_80mb_playlist_with_flat_memory`, ignored by default).
- An import holds the write lock for its whole transaction (about 1 s per 50k rows in release). Other writers wait for it: while a catalog import runs the busy wait is up to 600 s (`db::LONG_BUSY_TIMEOUT`) instead of the usual 5 s, so user writes (positions, favorites, settings) wait for the commit instead of failing.
