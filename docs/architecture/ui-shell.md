# UI shell, design system, and dashboard

Owner: U1. Covers `src/styles`, `src/ui`, `src/shell`, `src/i18n/index.ts`, and the `/dashboard` page. Contracts are SPEC C7, C10, C11, and C16.

## Visual direction: Night Tuner 2

The app is a TV and radio tuner, so the design borrows from a backlit radio dial at night.

- Surfaces are ink navy in dark mode and cool paper in light mode. Panels separate by surface steps, elevation and a quiet `--color-edge` hairline; the 3:1 `--color-border` is only on form controls (inputs, selects, switches, checkboxes).
- One accent at a time, amber by default; the user can pick one of seven in Settings > Appearance. The accents, OLED black, density and UI scale are in [appearance.md](appearance.md). Amber marks the primary action (one per view), focus, the active nav tick, the user's own progress, the playing or on-now marker and the playing channel's live progress; how far other programmes have run is neutral (Home's channel cards, Live TV's rows). Nothing decorative wears it (idle chips, saved and watched marks, segmented choices, icons), so it always means "here" or "go". Selection is the neutral `bg-selected` fill plus the tick, never an amber wash.
- The signature detail is the tuning tick, a short accent bar on the leading edge of the active rail item or selected row (the `tuning-tick` utility). Focus rings use the focus colour with a soft glow.
- Type: Inter Variable (self-hosted, `font-sans` and `font-display`) for all text and headings, on the type scale in [appearance.md](appearance.md); Barlow Semi Condensed 600 (`font-numeric`) for channel numbers, clocks, the channel-number OSD and LIVE pills. Arabic and CJK fall back to system faces per glyph.
- Artwork fallbacks are initials on a per-title hue gradient (`hueOf`, `initialsOf` in `Poster`), so missing posters still look intentional.
- Motion only answers user actions (dialogs, toasts, card lift). Everything runs under `motion-safe:`. `html[data-reduced-motion='true']` and the OS media query both turn animation off. The player OSD is the exception: it hides through its keyframe, so under reduced motion it keeps a 2.4 s duration with a no-fade `player-osd-still` animation (shown, then gone).

Dark is the default when the OS has no stated preference.

## Styles

- `src/styles/tokens.css` defines the C10 variables for `:root` / `[data-theme='dark']` and `[data-theme='light']`. Text pairs meet WCAG AA on their surfaces.
- `src/styles/globals.css`:
  - imports Tailwind and the tokens
  - declares `@custom-variant dark` keyed on `data-theme`
  - imports `fonts.css` (the self-hosted `@font-face` rules; Vite copies each woff2 into `dist/assets` with a hash)
  - maps tokens into `@theme`, which provides `bg-surface`, `text-fg-muted`, `border-edge`, `border-border`, `bg-hover`, `bg-selected`, `bg-accent-solid`, `bg-live-solid`, the type scale (`text-caption` to `text-display`), radii, `shadow-1` to `shadow-3`, `font-numeric`, `ease-enter` / `ease-exit`, and the rest
  - sets base styles, the focus ring (fields get a border and glow instead of the offset outline; forced-colours mode gets a system outline), and scrollbars
  - defines the keyframes (`shimmer`, `toast-in`/`-out`, `fade-in`/`-out`, `pop-in`/`-out`, `drawer-in`/`-out`, `sheet-in`/`-out`, `live-pulse`, `indeterminate`), utilities (`scrollbar-none`, `tabular`, `skeleton-surface`, `animate-shimmer`, `tuning-tick`), and cmdk styles
  - the skeleton shimmer is `@utility animate-shimmer` (used as `skeleton-surface motion-safe:animate-shimmer`): a band on an `::after` layer that sweeps by `transform` only, with `contain: paint` on the element, so the compositor runs it with no style recalc or repaint per frame. `src/ui/offscreen.ts` stops the loops nobody can see. `pauseWhenOffscreen` is a ref callback, used on the `Poster` placeholder while it loads and on the `LivePill` dot: one shared IntersectionObserver (64 px root margin) keeps `data-offscreen` on the element while it is out of view, set before the first observation, and globals.css turns its animation off there. While the window is hidden, `html[data-page-hidden]` pauses every shimmer, `live-pulse` and `indeterminate` loop, so a plain `Skeleton` pauses only then. Without IntersectionObserver nothing is marked. `live-pulse` runs three times as a live dot appears and then holds still, since an endless pulse kept the compositor drawing at the display rate wherever a LIVE badge showed; the player's live dot uses the same count (`LIVE_PULSES` in `Controls.tsx`).
- Layout variables: `--rail-width` 248px, `--rail-width-collapsed` 72px, `--header-height` 60px, `--panel-width` 340px, and `--page-gutter` (1rem, 1.5rem from `sm`, 2rem from `lg`), the side padding of the header and of every `Page`.

## UI primitives (`@/ui`, C11)

All of these are Radix-free and keyboard-complete. [design-system.md](design-system.md) says which to use when, with examples; this list covers behaviour.

- `Button`, `IconButton`, `buttonClass`, `TEXT_LINK`. A `loading` Button sets `aria-disabled` and `aria-busy` and ignores activation instead of using native `disabled`, so keyboard focus stays on it. IconButton shows the kit Tooltip from its `label` (or `tooltip`), with an optional `shortcut` as key caps; it takes no native `title`. Under `(pointer: coarse)` Button `sm`/`md`, IconButton, menu items and the toast's dismiss button are at least 44 px.
- Direction: primitives and shell use logical utilities (`start-*`/`end-*`, `ps-*`/`pe-*`, `border-s`/`border-e`, `text-start`) and `rtl:` variants for transforms and gradients, so they mirror in RTL; Tabs, VirtualGrid, the vod `gridNav` rails and grids, and the dashboard rails swap ArrowLeft and ArrowRight there, and Menu's `align` is logical. Provider text (titles, plots, programme names) carries `dir="auto"` with the `text-match-parent` utility, which aligns it to the parent's start (left, or right under an RTL parent) whatever its own script. The mini player docks with `inset-inline-end` (its saved offset is `{end, bottom}` in `player.mini.pos`; an older `{right, bottom}` still reads), so in RTL it sits bottom-left, clear of the rail on the right, and its arrow-key and drag moves follow `<html dir>`.
- `Input`, `Textarea`, `Select`, `SearchInput` and `fieldClass` for hand-built fields. In `SearchInput` the first Escape clears the field and the next one propagates; its clear button keeps focus in the field.
- `Switch` (role=switch; `Toggle` is a labelled Switch, the settings `SwitchRow` renders one), `Checkbox` (native, with a mixed state), `Radio` and `RadioGroup` (native), and `SegmentedControl` (a radiogroup of segments with roving focus; the settings `Segmented` and the subtitle style choices are built on it). Features draw none of these themselves; `src/ui/test/kit.test.tsx` checks.
- `Page`, `PageHeader`, `SectionHeader`, `BackButton`: the page scaffold.
- `Dialog`: portal, focus trap, Escape, focus restore, scroll lock, and `[data-autofocus]`. The trap stands down once the dialog starts closing, so an always-`open` Dialog that its parent unmounts still hands focus back to the opener. Closing plays an exit (the card pops out, the drawer slides back, the scrim fades) through `usePresence`, which keeps the layer mounted and inert until its `*-out` animation ends and unmounts at once where nothing animates (reduced motion, jsdom). Focus goes back as soon as `open` is false: the restore runs in a layout effect after React's own focus restore, which would otherwise put focus back inside the still-mounted panel. Menu and the toast stack exit the same way; a leaving toast drops `data-toast-id` and hands focus to its neighbour when its exit starts. The title row and footer are plain `div`s, because a portaled `<header>`/`<footer>` would add a second banner/contentinfo landmark.
- `Tabs` and `Menu`: roving focus. Menu also has type-ahead; its default trigger is an IconButton, and a custom trigger can take a `tooltip`. Pill Tabs share SegmentedControl's raised thumb.
- `Tooltip` (and `useTooltip`), `Kbd`, `Badge`, `LivePill`, `MetaLine`, `ProgressBar`. Tooltip adds its handlers and a ref to its one child, with no wrapper, shows after 400 ms on hover (at once within 500 ms of the last one, and at once on keyboard focus), never after a touch, and hides on Escape, a press, blur or scroll; `tone="glass"` over video, `side` may be logical (`inline-end`). Native `title` stays only on truncated text and on disabled buttons that explain why. `Kbd` and `comboKeys` print key names from `common` (`keyCtrl`, `keySpace`, `keyDelete`...: German "Strg", "Entf"), and media keys show their symbol with a translated spoken name (`keyNamePlayPause`...). Arrows and the macOS ⌘ and ⌥ stay symbols, so tooltip shortcuts (`shortcut="mod+k"`) show ⌘ on macOS.
- `Skeleton`, `SkeletonList`, `SkeletonGrid`
- `EmptyState` and `ErrorState`. ErrorState maps each `RpcErrorCode` to a translated title and next-step hint; the raw message (usually the core's English text) sits with the code in a folded "Technical details" disclosure. When the transport marks a `network` error with `details.transport === 'unreachable'`, it adds a translated body and a local-server hint. `errorDescription(err, redact?)` is the same for error toasts: the translated hint for the code leads and the raw message follows in small print (`data-error-message`). An error the UI raised itself (a plain `Error`, often already translated) leads with its own message and gets no code hint, and in the browser the `unsupported` hint drops the external-player advice (`errorHintUnsupportedWeb`). `EmptyState` sizes its icon itself. Toasts whose text is already localized keep their own (source errors, import toasts, the player's error overlay, multi-view).
- `Poster`: lazy, blur-up, with an initials fallback.
- `Pagination`
- `VirtualList` and `VirtualGrid`: listbox semantics, arrow, Page, Home, and End keys, Enter to select, and `onEndReached`. The grid's cursor moves to a cell on pointer down and on a right click, so its menu and keys act on that title; only keyboard focus (`:focus-visible`) starts it on the first cell.
- `toast()`, `useToast`, `ToastViewport`, `focusToasts()`. `toast()` works outside React and upserts by `id`. The stack is keyboard-reachable: `focusToasts()` (bound to F8 by the shell) focuses the newest toast's first button, Up and Down move between toasts, and Escape dismisses the focused one. Hovering or focusing a toast pauses its timer. When a focused toast goes away by any route, focus moves to the neighbouring toast, or back to where it was before F8 (falling back to `main#main`), never to `<body>`.
- `cn(...)` is `twMerge(clsx(...))` (tailwind-merge 3, pinned), extended with the theme's `shadow-1` to `shadow-3`, the type scale, `ease-enter`/`ease-exit` and `animate-*` names. Later classes win, so a caller's `className` overrides a primitive's default (`cn('px-3 bg-surface', 'px-6 bg-accent')` gives `px-6 bg-accent`).

## Shell (`@/shell`)

`ShellLayout` is the `/` layout route. It renders:

- a skip link
- three leaf components that render nothing but hold the shell's router and settings readers, so a navigation or a settings write re-renders them and not the layout (performance audit SH-1): `ShellEvents` (`useShellEvents`), `LastRoutePersistence` (`useLastRoutePersistence`) and `SettingsThemeSync` (`ThemeSync` fed from settings). The layout itself reads only `settings.language`, through `useSettingsValue`. `Rail`, `Header` and `PlayerDock` are memoized.
- the `Rail` (the only `nav` labelled "Main navigation", from 640 px up), in groups that `navigation.ts` defines for the rail, the phone's More sheet, the boot skeleton and the palette alike: Watch (Home, Live TV, the TV guide, Movies, Series, Sports, Multi-view; Search is in the list but `notInRail`, since from 640 px up the header always has a named way in: the "Search everything" box on most pages, and on pages that put their own field in the header slot (Favorites, Recently watched, My Videos, Sports, the TV guide, a source's Movies and Series) that field plus the palette button, which carries the same "Search everything" name. Ctrl+F opens the Search page, except on those pages, where it focuses their field. So the rail skips Search while the palette's Go to group and the phone's Search tab keep it), Library (My List, Favorites, Lists, Recently watched, Downloads, My Videos, Scheduled, Stats), and Sources, from `sources.list` with `railLinks(source)` per C7 (an imported Xtream source drops Radio, Movies and Series links whose counts are 0, a Stalker one drops Radio only), an Add button in the group's label and Manage sources at its end. With exactly one source the group is one row: the source's monogram and name, a link to the Sources page that stands for Manage sources (its name and tooltip end in "Manage sources", and after a failed refresh the tooltip says what the red dot means; collapsed it is the monogram alone, not a menu), since every link its entry opened was a Watch or Library row already. Its Radio, the one link no other row had, becomes a Watch row after Live TV (`loneSourceRadio`), and Live TV is then no longer current on the radio pages. Live TV, Movies and Series in Watch open a section of a source (`watchLinks` and `sectionTarget` in `navigation.ts`), so the three most used pages sit at the top rather than inside a source's entry at the foot of the rail: Live TV goes where the phone tab's Live TV goes (`liveTabTarget`, so a VOD-only account opens on its movies), and Movies and Series go to the source on show (`routeSourceId`), else the last one opened (`tsrust.lastSource`), when it has the section, else to the first source that has it by `railLinkIds`' rules (always for a Stalker portal and for an Xtream account before its first import, otherwise by the counts). Movies or Series is left out while no source has it. With no sources the three lead to the Sources page with the row's section in `for` (`/sources?for=live`, `noSourcesTarget`), as the phone tab's Live TV does, and stay current there (`sectionCurrent` reads `sourcesFor`) while Manage sources does not. That holds only while there are no sources: the query outlives the first add, and from then on the Sources page marks Manage sources (or the lone source's row) alone; every row whose page has nothing to show without a source is dimmed (`dim`), which leaves out only Home, Search, Sports and Lists (`noSourceNeeded`); while the sources load they lead there too, undimmed, so the rows hold their place. They are current by `sectionCurrent`, not by their path: Live TV on any source's live pages and the catch-up archive (`isLiveRoute` without radio, whose pages light Radio), Movies and Series on a section's pages and what `railLinkCurrent` counts beside them (a movie's detail and player), in any source. A rest on them prefetches like the other links, and the icon rail shows them with their names as tooltips. The footer holds Settings, the keyboard shortcuts button (expanded rail only; the icon rail has no room for it, and `?`, the palette and Settings reach the same list) and collapse or hide. Library shows My List, Favorites, Lists and Recently watched, then a More row (a disclosure in the shape of a link row whose chevron points to the inline end while folded and down while open, as a source entry's does; an icon with a tooltip in the icon rail) that unfolds the less used Downloads, My Videos, Scheduled and Watch stats in place (`more` in `LIBRARY_LINKS`). More starts folded and keeps a press across launches (localStorage `tsrust.railLibraryMore`); folded, it opens again whenever one of its pages opens, including from another of them, so the current page is never a hidden link (the reopening is not saved). Folded, the rail's rows fit a 768 px tall window with the sources in view. The Library label itself no longer folds the group. The palette and the phone's More sheet list all eight. With no sources Library is dimmed but for Lists, where a list can be created before any source. The sources are an accordion: opening one closes the one that was open, so a second source never pushes Library and the group labels out of the rail. The one the user left open is remembered (`tsrust.railSource`: its id, or empty after closing it); nothing else opens by default (`defaultOpenSource`). Every leading glyph sits in one 20 px box (`RAIL_GLYPH`; the source monograms are that size too), so link labels and source names start on one line. The group labels (Library, Sources) are sticky inside their scrolling block, so they stay readable while their links scroll under them; that block fades about a row's height at its foot (`railFadeMask(…, '3rem')`) and not at its top, where the sticky label is the edge. A source's links are current by `railLinkCurrent`: their own path and the pages under it, plus the pages beside it, a movie's detail and player (`/s/:id/movie/:itemId`) for Movies and the catch-up archive (`/live/archive/:id/…`) for Live TV. The Watch links and the rest scroll apart: the Watch list is capped at the larger of half the rail's middle and all of it but 10rem (`RAIL_PRIMARY_MAX`), and Library and the sources take the rest, so a source's page reveals its link without pushing Home or the guide out of view. The source of the current route (`routeSourceId`: `/s/:id/...`, and the catch-up archive `/live/archive/:id/...`, which sits outside `/s/:id`) is marked, and with two or more sources it is opened too (in the render the sources arrive in, when they load after the page); a lone source has no entry to open, as the Watch links already mark its pages. With no sources the group shows one dashed "Add source" row, except on Home and Sources, whose own welcome and onboarding say the same.
- the `Header` (the only `banner`), with title, subtitle, actions, a panel toggle, the search slot and the theme toggle. Its side padding is `--page-gutter`, so the title lines up with `Page` content. The search slot has one width and place on every page (`HEADER_SEARCH_WIDTH`, `clamp(15rem, 24vw, 22rem)`, right before the theme toggle) and one look: the `bg-surface-2` fill, the control border and a trailing key hint in compact caps (`Kbd size="sm"`). A page that searches its own content puts its field there with a Ctrl F hint (below 640 px it folds into a search icon that unfolds over the title while in use). `HeaderSearch` can also hand the page the field itself (`inputRef`), a focus handler, a name longer than the placeholder (`label`), the id of results it drives (`controls`, its `aria-controls`) and `disabled`, which the TV guide uses for the results panel it hangs under the field, and the palette keeps a small button before the field (`data-testid="header-palette"`), named "Search everything" like the box it replaces and drawn with a `TextSearch` glyph so it does not read as a second magnifier for the field; every other page shows "Search everything" with Ctrl K, which opens the command palette (`data-testid="open-palette"`). Below 640 px the header has neither that button nor the theme toggle: the tab bar carries search, and the theme is in Settings and the palette. The title is a styled `<p>`, not a heading: every page renders its own single `<h1>`, so the header must not add a second one. The header also sets `document.title` to `<title> · Tsrust IPTV` (just the app name when no page title is set). A page can name the window differently with `documentTitle`: a movie or series watch view puts the section (Movies, Series) in the header, since the stage's own bar right below names the title, and keeps the title in the window, the tab and the history entry. Detail pages (movie, series, actor) lead the header with `back` (the kit BackButton, which runs the page's `useGoBack`, as Escape does) and set `section`: the header names the section ("Movies", with the source after it when there are several) while the page's own large title is on screen, and fades the title in once that h1 has scrolled away (`useHeaderTitleAnchor`, an IntersectionObserver on the element, `titleScrolledAway` in the store). Below 640 px the header shows Back alone while the h1 is on screen, with no section beside it, so the page's own title, `text-headline` there, is the largest type on a phone; once the h1 scrolls away the title comes in after Back as on wider windows. Back keeps its plain name at every width: it goes back in history, which is often Home, Search or another title rather than the section. The window title is the item's throughout. The hero has no Back of its own.
- in web mode, the offline strip under the header (`ConnectionBanner`, `connection.tsx`): after the event socket has been down for 3 s (`OFFLINE_GRACE_MS`) it says the app is reconnecting, with Retry, while the rail and Home wait quietly instead of each showing an error; when the socket reopens it says "Back online" for 2.5 s and goes. The desktop app never loses its core, so it never shows.
- `main#main` with the `Outlet`. It is a flex column with `min-h-0` inside a row of definite height (the root is `h-dvh`; header and footer are `shrink-0`), at every width from 800 to 2560 px. A page either grows and lets `main` scroll, or fills it with `flex-1 min-h-0` (or `h-full`) and scrolls inside, which gives `VirtualList` / `VirtualGrid` a bounded scroll parent.
- the `ContextPanel`: inline at 1440px and wider, a drawer below that. No page sets one at present; Settings has its own section nav (settings.md).
- below 640 px, the `TabBar` (CB-PHONE-NAV) in place of the rail: Home, Live TV (the source on show, else the last one the user opened, `tsrust.lastSource`, else the first with channels; `/sources` with none), the TV guide, Search, and More. More opens a bottom sheet (the kit Dialog's `sheet`, `MoreSheet` in `TabBar.tsx`) that leads with Watch: tiles for the rail's Watch rows the bar has no tab for (`sheetWatchLinks`: Movies and Series from `watchLinks`, marked by `sectionCurrent`, Sports and Multi-view, and with one source its Radio), so Movies is two taps away rather than a chip inside a source's card. Then the Library tiles, the sources, Manage sources and Settings. Two or more sources each get a card with chips for their Live TV, Radio, Movies and Series; one source is a single row to the Sources page named "<source>, Manage sources", which replaces the Manage sources row, as in the rail. While the page on show lives in the sheet, More carries `aria-current="true"` as well as the tick, and a link in the sheet leaves focus on `#main` of the new page rather than back on More. The bar sits in the shell's column under the outlet, so pages need no padding for it. While it shows, `<html>` carries `--shell-bottom-inset` (its height plus the home indicator's safe area), which the mini player docks above and clamps its drags to; the bar has `data-toast-avoid`, so toasts stack above it.
- `ExternalPlaybackFooter` and `PlayerDock`, both from `@/features/player`
- `CommandPalette`, `ShortcutOverlay`, and `ToastViewport`
- `SecureContextNotice`: in a browser that is not a secure context (plain HTTP to another machine), a toast once per browser that names what the browser turned off and links to [server.md](server.md#https-and-secure-context)
- `OnboardingHost` (Run 3 C7), lazy from `@/features/onboarding/host`, not the barrel, so the release notes and their icons stay out of the shell chunk. It decides on the first-run tour and What's new and shows them; see onboarding.md.

Below 640 px there is no rail: the tab bar stands in. From 640 px the rail collapses to icons below 1024px or when the user collapses it. That preference is stored in localStorage. Below 1024px the rail never expands, so in the collapsed rail each source's mark is a `Menu` trigger that lists the source's `railLinks` (Live TV, Radio, Movies, Series, Favorites, Recent, as its kind has them); the item for the current page gets an accent icon and a screen-reader "current page" hint (`railCurrentPage`). An M3U source lists Radio only once its radio probe (`catalog.channels` with `radio: true`, limit 1) has answered, and in the collapsed rail that probe starts when the mark is hovered or focused.

Below 1024px the collapse toggle is replaced by "Hide sidebar" (`hideRail`, `toggleRailHidden` in the shell store, localStorage `tsrust.railHidden`): the layout then renders no rail, and the header leads with "Show sidebar" (`showRail`, `data-testid="rail-show"`). Each button moves focus to the other as it goes (`flushSync`, then focus). The flag only applies below 1024px; a wider window always shows the rail, so it cannot go missing on a desktop. While the rail is hidden the tour's `live` and `vod` anchors are absent and those steps show as centred cards.

Tour anchors (`[data-tour]`, read by the onboarding tour's `findAnchor`, which takes the first laid-out match inside the window):

- `live`: the Watch group's Live TV row, collapsed or expanded, which leads where the phone tab does (`liveTabTarget`: the source last opened, else the first with live channels and no import error); below 640 px the tab bar's Live TV tab. The rail's source entries carried it until Live TV moved to the top of Watch.
- `vod`: the Watch group's Movies row, and the My List rail link, which `findAnchor` reaches when no source has movies and the rail leaves Movies out. The phone has no Movies tab, so the step shows as a centred card there.
- `search`: from 640 px up, the header's search field when the page has one, otherwise its "Search everything" button; below 640 px the tab bar's Search tab, and the header's field does not carry it, so exactly one element on screen has the anchor at every width. The automatic first-run tour is a single card on this anchor (onboarding.md).

The palette's Settings group has "Take the tour" (`help.tour`) and "What's new" (`help.whatsNew`); Settings > About has the same two buttons. All four import `openTour` / `openWhatsNew` from `@/features/onboarding/store`, which has no UI imports.

The palette's Settings group lists every section as "Settings: <name>" with the settings page's own section names (`settings<Section>` in `shell.json`), and finds a section by the rows it holds (`settings<Section>Keywords`, in the UI language and in English): poster size and the Home screen rails under Appearance, the recordings folder under Recording, the image cache and Reset under Backup and storage.

Palette matching (`paletteFilter`): an item matches only when every typed word appears unbroken in its title or keywords, case-insensitive; title matches rank above keyword-only ones, and cmdk's score orders the matches inside each band. Internal ids never match. While a query is typed, groups are ordered by their best match. The library and guide groups answer after a pause and can rank above the rows already shown; cmdk would keep its selection on the row it had, which then slid down the list, so the palette holds cmdk's value itself and puts it back on the first row after each answer (and scrolls to the top), until the user picks a row with the arrow, Home, End or Page keys or the pointer. A new query starts over.

The palette's "Favorites and recent" group (`groupFavoritesRecent`) lists favourites and recently watched items whose titles match the query (`matchContent`: one entry per item, best first, at most 8, favourites ahead of recent items on equal scores). It reads `favorites.list` and `recent.list` with the dashboard's arguments (`{ limit: 60 }`), so Home's cache serves it, and only while the palette is open, so typing sends no requests. Items of a removed source, or one waiting out its delete-undo window, are left out. A channel or radio station plays in the dock through `playItem`, as from a dashboard card; a movie or series opens `/s/<sourceId>/<movie|series>/<itemId>`. The group comes first, so a tie with a command goes to the content, and the library groups below never rank above it: each scores at most what this group does, so "NBA 05" from League Pass, which starts with "nba", stays under the "US| NBA TV FHD" the user watches.

The palette's "Channels" and "Movies and series" groups (`useCatalogItems`) are the library's own matches, so a channel, movie or series nobody has favourited or watched is found without going through "Search for". They come from `catalog.search` with the Search page's first-page arguments (`{ query, limit: searchRequestLimit(SEARCH_LIMIT) }`, every source), asked 120 ms after typing stops and only while the palette is open, so "Search for" then opens on an answer already in the cache. The core caps each type at that limit whatever the library's size; the palette lists the first 4 channels and the first 4 movies and series that still match what is typed (the query an answer is for counts as its keywords, since the core folds diacritics and finds a renamed channel by its provider name), and leaves out items the "Favorites and recent" group already lists. A channel's row names its group (and its source when there are several) and plays it in the dock through `playFromShell`; a movie or series opens its detail page, where a parental lock still asks for the PIN.

The palette's "Go to" group lists the Watch and Library links in rail order, then Manage sources, Add source and Settings. It builds the Watch part with the rail's `watchLinks` and the same source (the route's, else `tsrust.lastSource`), so its Live TV, Movies and Series open what the rail's do and drop out with them; they also answer "channels", "films" and "shows".

With nothing typed the palette opens on the last few channels (their logos), the titles to resume (their posters, cropped into the same tile; a series resumes with its queue, `playFromShell`) and a few suggested actions. Its list is capped at `min(64vh, 32rem)` and fades out at its foot while more of it is below (`railFadeMask`), so the row the edge cuts reads as continuing.

The palette's "Guide programmes" group (`groupProgrammes`) lists up to 5 programmes whose titles match the query, from `epg.search` of every visible source (`useProgrammeSearch` in `src/features/live/guide/programmeSearch.ts`), asked 200 ms after typing stops and only while the palette is open, with the Search page's own limit (50 per source), so "Search for" opens with its programmes cached. A show on several channels at once (the same title and start) is one row that names the first channel, says how many channels carry it (`foldProgrammeHits`; from 640 px up, as a phone's row needs the room for its title) and opens the guide at that first one, so the five rows are five shows rather than one show five times. The core folds diacritics, so the typed words count as each hit's keywords and the palette's own filter keeps it. A hit opens the guide at the programme (`guideHitLink`: `/epg?source=<id>&at=<start>` with the hit in the router state), where the channel's row takes the cursor and is marked, as for a hit of the guide's own search.

Page API, which works without a provider (zustand):

- `useShell()` returns `{ setHeader, setContextPanel }`. Both reset on unmount if the page still owns them.
- `useShellHeader(header, deps)`
- `registerCommands(cmds)` returns an unregister function. Commands appear in the palette.
- `useShortcut(combo, handler, { description, area, enabled, allowInInput, allowInModal, global, when, priority })`
  - There is one window listener (bubble phase, so focused widgets such as Dialog, SearchInput, Menu, and VirtualList handle their keys first and claim them with `preventDefault`). Among the matching entries the highest `priority` (default 0) wins, then the most recently registered. The multi-view page gives its F, M and L priority 1, so they beat the playback keys of the same letters, which register again (as newer) whenever main playback starts.
  - `when(e)` is checked at key time after the combo matched; false skips the entry as if it were not registered, so an older entry or the browser default gets the key. The playback keys use it to leave Space, the arrows and Page Up/Down to the page while the player is only the mini dock (`playerOwnsPageKeys`, players.md).
  - Once an entry matches, the registry calls `preventDefault()` and `stopPropagation()` before it runs the handler, so browser defaults (Space scrolling, `/` quick find, F11, Ctrl+F/R) never fire, even if the handler throws (errors are logged).
  - Shortcuts are skipped while the user is typing (input, textarea, select, contenteditable), unless `allowInInput` is set. A skipped key keeps its default.
  - Plain `space`/`enter` shortcuts are skipped when a button, link, checkbox, option, tab, or similar control has focus, so the key activates the control. Plain arrow, Home/End, and Page keys are skipped on controls that use them (`isArrowTarget`): selects, range and radio inputs (the browser moves the checked radio), and the slider, spinbutton, scrollbar, listbox, option, grid, menu, tab, radio and tree roles.
  - While an aria-modal dialog is open, only `escape` and `allowInModal` shortcuts fire; `mod+*` combos are no exception, so Ctrl+B or Ctrl+Alt+L do nothing over a dialog. The registry looks for one only once a shortcut matches that it would block, not on every keydown (performance audit SH-7).
  - `global: true` bypasses all of the above (typing, focused controls, modals).
- `useTheme()` and `persistTheme(theme)`
- `openPalette()` and `openShortcutHelp()`
- `openSearch(navigate)` goes to `/search` with the cursor in its field, as `mod+f` does when the page has no search field of its own. `focusSearchWhenReady({ skip })` (in `focusSearch.ts`) focuses the first `SEARCH_FIELD` (`[data-page-search], [data-shell-search]`) other than `skip`, polling every 50 ms for up to 3 s, because the search page loads lazily and its header field mounts only after the chunk arrives. `openSearch` passes the leaving page's own field as `skip`: it is still mounted for a moment after `navigate()`, and focusing it would drop focus on `<body>` when it unmounts.

Shortcuts the shell owns: `mod+k` (toggles the palette, including from inside its input; cmdk's `vimBindings` are off so its Ctrl+K never swallows the key; over another dialog it does not open), `mod+f` (focuses `[data-shell-search]` or `[data-page-search]`, otherwise goes to `/search`), `mod+r` (`/recent`, in the desktop app only: in a browser Ctrl+R is the reload key, so the app leaves it alone there and the overlay does not list it), `?` (overlay), `mod+shift+l` (flip light/dark, same as the header button; "match system" is in the palette and Settings; also in fields and dialogs), `f8` (jump to notifications), `f11` (fullscreen, `toggleFullscreenKey`: the player's fullscreen, as `f`, while the dock holds a source that is not playing externally; otherwise element fullscreen on the document, which the desktop window follows through `bindWindowFullscreen`, since WebView2 has no F11 of its own; registered with `allowInInput` and `allowInModal`, so it also works in fields and dialogs), and `escape` (closes the palette, then the overlay, then the panel, then blurs). `mod+f` and `mod+r` leave the page, so `navigationKeyBlocked` makes them do nothing over a dialog or in a text field, where they would throw away typed text (the Add source URL and credentials); they still claim the key there, so the browser neither reloads nor opens its find bar, and they still run from the command palette. The overlay's list is a focusable region so arrow and Page keys scroll it. While closed, `ShortcutOverlay` reads only `helpOpen`; the registry subscription (`useShortcutList`), the merged list and the filter live in a dialog mounted only while it is open, so a page registering or toggling shortcuts costs the closed overlay no render, and the filter starts empty each time. The overlay merges registered shortcuts with the documented C16 list (`DOCUMENTED_SHORTCUTS`), so playback and live keys are listed even when those pages are not mounted. `shortcutReference(registered, t)` in `ShortcutOverlay.tsx` builds that merged, grouped list, with each area's heading translated through `SHORTCUT_AREA_KEYS`; Settings > Shortcuts calls the same function, so the two lists always match. A new documented area needs an entry in `SHORTCUT_AREA_KEYS` (and in `AREA_ORDER` for its place), or its raw id shows as the heading. The groups run Everywhere, Playback, the seek bar, Live TV and the guide first, the rare ones (parental controls, then the tour) last. The overlay shows one row per action (`mergeShortcutRows`): keys that do the same thing share a row, "Enter or Down", as in Settings. Its group labels are sentence-case captions, like the rail's and the palette's.

Side effects (`effects.ts`):

- `bindEventInvalidation(EVENT_INVALIDATION)`. The shell's map adds prefixes to the api's `DEFAULT_EVENT_INVALIDATION` (`src/api/query.ts`). It has no `downloads.update` entry: the default refetches only `downloads.list` and the `myvideos.` queries, so a progress burst never refetches `downloads.dir` (a `downloads.` prefix here used to).
- `settings.changed`: `bindEventInvalidation` has already written the new settings into the query cache; the shell handler invalidates `sources.schedule` only when `sourceRefreshIntervalHours` changed, and checks `englishOnly`. It also compares the Live TV quality filter in effect (`liveMinQuality`, and `liveHideUntagged` while a minimum is set; `liveQualityKey`) with the last one seen, and on a change invalidates what the core filters by it (`LIVE_QUALITY_PREFIXES`: `catalog.`, `favorites.`, `recent.`, `lists.` and `epg.search`). Failover alternates are not a query: the player keeps them in its own cache and asks for them again itself (failover.md). As with the other two, the first value seen is a baseline, not a change. The filter is tracked with an explicit "not seen yet" (`undefined`), not `??=`: its off value is `null`, so the optimistic cache write from the Live TV picker would become the baseline and the `settings.changed` echo would refetch nothing. A `lastRoute`-only write sends no `settings.changed` at all (settings.md).
- `import.progress` shows one updating toast per source, with progress.
  - Dedupe with the Sources page (decision): while `/sources` is the active route, the shell shows no progress or `done` toast and dismisses any `import-<sourceId>` toast it showed earlier, because that page already shows per-card progress and its add dialog and refresh flow toast their own success ("Added X"). Coalescing by toast id was not an option: the page's toasts carry no id, and the shell does not edit feature code. Errors still toast on `/sources` (a refresh that returns `lastError` gets no page toast), without the "Open Sources" action. On every other route (auto refresh, deep links, an import still running after the user left the page) the shell toasts every phase. The rule is `importToastPolicy(phase, isSourcesRoute(pathname))`, read from a ref so the event subscription is not rebuilt on navigation.
  - The progress line (`importProgressText`) is worded like the Sources page's counts: an M3U download reports bytes while it fetches, shown as a size (`formatFileSize`); every other count is grouped in the UI language's number format (`formatCount`). A source not cached yet counts as M3U when it fetches without a message.
  - `holdImportToasts()` holds back every per-source import toast (progress, ready, failed, cancelled) while a surface reports the whole run itself. Settings > Backup and storage (`BackupSection.tsx`) holds them around `backup.import`, which imports each restored source in the core, and reports the result in its own toast and result card. Home's welcome holds them while its Add source dialog is open, which shows the import's progress and toasts its own success, as the Sources page's dialog does there. It returns a release function that takes effect `IMPORT_TOAST_HOLD_GRACE_MS` (1 s) later, because the last events can trail the RPC's reply. Holds count, so overlapping ones stack. A held or dismissed toast is removed, and a cancelled or failed import still invalidates `sources.`.
- `deeplink.open` maps `iptv://search?q=` to `/search?q=`, and add links through the Sources feature's `addSourcePathFromDeepLink`: `iptv://add?url=<url>[&kind=m3u|xtream|stalker]` and `iptv://add/<encoded url>` open `/sources?add=<url>[&kind=]`, a bare `iptv://add` an empty form, and a target that is not http(s) is ignored.
- In web mode, a toast appears if the event stream stays closed for 3 s, including before it first opens; it shows once per outage and goes away when the stream opens.
- Language sync from `settings.language`.
- `lastRoute` (`useLastRoutePersistence`) saves the current route, query included, through `settings.update`. A move to a new pathname is saved after a 1200 ms debounce (`LAST_ROUTE_DEBOUNCE_MS`). A query-only change on the same screen (a search's `?q=`, a filter) starts no timer, because each write costs a core settings rebuild: it is saved on `pagehide` or when the document becomes hidden, unless a move to another screen saves that one first. `pagehide` and hiding also save a route still inside its debounce. `/` and `?add=` routes are never saved (`isRestorableRoute`). The core announces no `settings.changed` for a `lastRoute`-only change, so the reply goes straight into the `settings.get` cache; `StartupRedirect` does the same when it forgets a dead saved screen. A failed write is tried again on the next navigation.
- Window state on desktop. Decision: `tauri-plugin-window-state` owns the OS window. It restores size, position and the maximized state before the window is shown, so the shell never calls `setSize`, `setPosition`, or `maximize`. A second restore from the webview would land after first paint and make the window jump, and the two stores could disagree. Fullscreen, the window frame and visibility are left out of the restore (`StateFlags` in `crates/iptv-tauri/src/lib.rs`): picture-in-picture and the player's fullscreen turn the frame off, the app always opens framed and not fullscreen, and the window shows when the page has painted its first frame (`reveal_window`; a fallback timer covers a page that never renders). The shell only mirrors geometry into the core: it reads `window.getState` once to seed the last normal (unmaximized) geometry, then writes `window.setState` (C4) with an 800 ms debounce on move and resize, skipping minimized windows and keeping the normal geometry while maximized or fullscreen. That keeps the core copy accurate for diagnostics and backups. What the plugin does not cover stays with the shell: rail collapse and hiding in localStorage (`tsrust.railCollapsed`, `tsrust.railHidden`), the last route in `settings.lastRoute`, and the theme in `settings.theme` mirrored to localStorage.

Theme: `settings.theme` is mirrored to localStorage (`tsrust.theme`) and applied before the first paint by `public/theme-boot.js`, then again when `theme.tsx` loads, before React mounts, so there is no flash ([appearance.md](appearance.md)). `data-theme` is set on `<html>`.

`persistTheme(theme)` applies the choice locally and in the settings cache at once, then calls `settings.update`; only the newest call writes its reply into the cache. A write that fails with `network` or `timeout` (web mode with the server down) stays pending and is sent again when the event socket reopens after a drop or when any RPC gets an answer (`onServerAnswered`). Until the server confirms it, `ThemeSync` ignores the server's theme, so the settings refetch after a reconnect cannot flip it back. A write the server answers and refuses is not resent; the local choice stays and settings reconcile on the next load.

Routes: `src/shell/routes.tsx` exports `shellRoutes`:

- the index route is `StartupRedirect`. It goes to `lastRoute` when `startupBehavior` is `restore-last-view`, otherwise to `/dashboard`, or to `/sources` when `showDashboard` is off. On desktop it first waits for the one `app.pendingDeepLinks` pull (`pullStartupDeepLink`, memoized); a cold-start link wins and becomes the only navigation, so a lazy target route or late settings cannot override it. `useShellEvents` navigates to that link itself only when the app did not start at `/` (`src/shell/test/deepLinkStartup.test.tsx`).
- `dashboard` renders `DashboardPage`.

Wire them as:

```tsx
{ path: '/', element: <ShellLayout />, children: [...shellRoutes, ...featureRoutes] }
```

The shell tests mount `shellRoutes` that way. The app's own tree (`src/routes.tsx`) wires the same two routes as `shellChildRoutes`, with `dashboard` as a lazy chunk loaded through `loadDashboard` (exported by `StartupRedirect.tsx`); the index route itself is not lazy. `StartupRedirect` restores the saved screen only while it still exists: `src/routes.tsx` passes `isKnownPath` (a path that some route other than the not-found page renders), a screen of a source (`/s/:id/...`, and the catch-up archive `/live/archive/:id/...`) waits for `sources.list`, and a `/lists/:id` screen waits for `lists.list`. A dead screen goes to the default target, and that target is written back as `lastRoute`. A failed list restores the screen anyway. It starts the dashboard chunk download only when the startup target is `/dashboard`: once settings are in, the lists it needs too, and no startup deep link is pending (on desktop this can run while the deep-link pull is still out). Restoring any other screen downloads no dashboard code.

Before the router mounts, `src/main.tsx` prefetches `settings.get` and `sources.list` into the query cache (`queryClient.prefetchQuery` under the same `rpcKey` the pages use, with no abort signal), while the language and, on desktop, the image cache base load. The startup redirect, the rail and the dashboard then join those two requests instead of sending their own.

`/dashboard` renders one visually hidden `<h1>` ("Home") in every state (loading, welcome, error, rails); rail and hero titles are `h2`. It shows the following rails. Each one is toggled by `settings.dashboardRails`.

- hero: a carousel of continue-watching entries and recently added titles with artwork (appearance.md, Dashboard hero)
- continue watching
- On now: what airs now on recently watched and favourite channels (follows `dashboardRails.liveFavorites`; there is no setting of its own yet)
- My List (`settings.dashboardRails.myList`), then one rail per custom list with "Show on Home" on (`CustomListRails` from `src/features/lists/rails`, in list order; a list's own `onDashboard` flag decides, not `dashboardRails`; see lists.md)
- favorite channels: live and radio favorites, with EPG now-playing from `epg.nowNext` (asked only while Home's live rails are on, and asked again once a programme in the answer has ended, `firstProgrammeEnd`, not every minute; a minute tick moves the progress bars)
- channels in the most used source, when no other live rail has anything to show (an M3U source on first run)
- recently watched channels, drawn as the favourites are: what is on and how far it has run, from the same `epg.nowNext` call (their channels are asked about on top of On now's share). A channel card names its source only when Home has two or more; with one, a card with no programme says Live TV or Radio
- favorite movies and series
- your sources: ranked by latest use, then refresh time
- recently added: `catalog.recentlyAdded` for movies and series, merged
- trending: `tmdb.trending`, only when TMDB is enabled

Above the rails, `AccountAlerts` lists Xtream and Stalker subscriptions that expired or expire within `settings.accountExpiryWarnDays` (from `account.statusAll`; nothing when that is 0 or every source is M3U), expired first. Each row links to `/sources?account=<id>`, which opens that source's subscription tab, and can be dismissed. A dismissal is stored in localStorage (`tsrust.accountAlerts.dismissed`) per source and expiry date, so a renewed subscription warns again. See account.md.

Rails show a skeleton while loading and an inline error with retry on failure, and they render nothing when empty. With no sources, the page is a welcome (`Welcome.tsx`): the brand mark, one line on what the app does, and the Sources page's own onboarding tiles (`Onboarding` from `src/features/sources`) with its privacy line and its "Import a backup" link. On a phone the mark and the onboarding's lead line go and the heading is a headline, so the tiles start on the first screen. A tile opens the Add source dialog right there on the kind it names, so Cancel leaves the user on Home. The first source, once imported, opens on its own page (`sourceHomePath`: its live channels, else its movies or series), where the tour's coach mark starts (SS-6); "Close, keep importing" leaves the user on Home, which turns into the dashboard. With sources but nothing to show yet (an import still running, every rail switched off), "Get started" tiles lead to the most used source's home, the TV guide (when there are channels) and Search. The hero's slides have a menu (the same items as the cards' menus) beside Details; while it is open the rotation waits. Keyboard: each rail is one tab stop. ## i18n

`src/i18n/index.ts` bundles only `src/i18n/en/*.json` eagerly (the fallback, exported as `resources`). Every other `src/i18n/<lang>/<ns>.json` loads lazily: each language folder's `index.ts` gathers its namespaces (an eager `import.meta.glob`), `src/i18n/lazyLocales.ts` maps each language to a dynamic import of that module (18 entries, in the entry chunk), and `vite.config.ts` puts the folder's JSON files and `index.ts` in one `locale-<lang>` chunk, so a language loads in one request ([performance.md](performance.md)). `loadLanguage(code)` loads all namespaces of a folder and adds them with `addResourceBundle` under the BCP 47 key (`by` becomes `be`, `zhtw` becomes `zh-TW`); loads are cached and a failed one is retried next time. `applyLanguage(code)` loads first, then calls `changeLanguage`, stores the choice in localStorage (`tsrust.language`), and sets `lang` and `dir`; when switches overlap, the newest request wins, and a failed load falls back to English. Importing the module initializes i18next in English and starts loading the stored language; `initI18n(lang?)` resolves once that language is active (it never rejects), and `main.tsx` awaits it before the first render so there is no English flash. It also exports `NAMESPACES`, `LANGUAGES` (19 entries, with `rtl` for Arabic; defined in the side-effect-free `languages.ts`), and `i18n`.

Every `Intl` constructor takes its locale from `intlLocale` (`src/lib/intl.ts`): `ary` becomes `ar` (Intl has no Moroccan Arabic data and would use the machine's locale), `by` becomes `be`, `zhtw` `zh-TW`, `zh` `zh-CN`, and anything else comes from the LANGUAGES table, falling back to English. i18next's built-in formats (`{{count, number}}` and the rest) are routed through it too, and counts that can pass 1,000 use `{{count, number}}`. Track language names (`trackLanguageName` in `features/player/engines.ts`) follow the app language, not the OS. Lists of names (genres, creators, the downloads summary) use `formatList` (`Intl.ListFormat`, conjunction); fact lists in labels join with `listSeparator` ("、" for Chinese and Japanese, "، " for Arabic). `numberFormat`, `dateTimeFormat` and `relativeTimeFormat` in the same module cache one formatter per locale and option set, so list rows that format on every render build none. Moving the 18 other locales out of the main chunk took it from 2,689.72 kB (gzip 768.26 kB) to 1,024.37 kB (gzip 313.66 kB). Keys are flat camelCase per namespace, and plurals use `_one` / `_other`.
