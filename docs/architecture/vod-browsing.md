# VOD browsing: year filter and watched

Code: `crates/iptv-core/src/catalog/vodfilter.rs` and `crates/iptv-core/src/userstate/watched.rs` (core), and `src/features/vod/` (UI: `lib/years.ts`, `lib/paging.ts`, `components/VodFilterBar.tsx`, `hooks/useWatched.ts`, `pages/CategoryGridPage.tsx`, `pages/SeriesDetailPage.tsx`). Tests: `crates/iptv-core/tests/vod_filters.rs`, `crates/iptv-core/tests/l2_data_series_watched.rs` (a series' row following its episodes), unit tests in `vodfilter.rs`, `src/features/vod/test/vodFilters.test.tsx`, and `e2e/vod-filters.spec.ts`.

Run 2 contract C4 adds three ways to narrow a Movies or Series grid: a release-year range, a watched tick on each poster, and a "Hide watched" switch. Series pages also get "Mark series watched".

## What "watched" means

A movie or series is watched when it has an item-level row in `playback_positions` (`episode_id = ''`) with `watched = 1`. Run 1's `WatchlistEntry.watched` uses the same definition.

- A movie gets the row when playback finishes it (a save at 95 % of the duration or later) or when someone marks it watched.
- A movie loses it once it is really played again. The core keeps `watched = 1` on a movie's partial save, so a replay under 5% of the duration leaves the tick, Hide watched and Continue Watching as they were, and the next play starts over. The first save of a playback past 5% asks for the row and, when it is watched, removes it and writes it again unwatched (`unwatchReplay` in the player store): the tick goes, the movie page offers Resume and Start over without "Watched", and Home's Continue Watching resumes it. At 95% the film is finished and watched again. A watched row with a position between 5% and 95% (saved before this, or when the clearing failed) is still a resume point (`isWatchedReplay`, used by `isResumable`). An episode loses its flag on any save past 5 s, so a rewatched episode becomes the series' place to resume.
- A series gets the row from "Mark series watched" (`userstate.setWatched` without an episode id), and also when an episode write leaves every episode the provider lists watched (`watched::sync_series_mark`, the same rule as the detail page's `seriesWatchedWrite`). The core checks after a live `positions.set` that finishes an episode and after a `userstate.setWatched` episode mark, so finishing the last episode in the player or marking it from Recently watched counts too. The episode list comes from the Xtream series cache, else from the provider within 4 s (Stalker always asks the portal); an m3u series has it in its row (m3u.md, Series). When the list is unknown (the provider down or too slow), or the write is a dated undo or restore, nothing changes. Unmarking any episode clears the series row.
- Unmarking deletes the row (`set_watched(.., false)` removes the position), so the resume point goes too. The grid's Undo toast restores the captured rows.

## Core

### `catalog.movies` / `catalog.series` filters

`VodListArgs` takes `yearFrom?`, `yearTo?` and `hideWatched?`. The catalog builds a `VodFilter` and checks it with `vodfilter::validate`: each bound must be in 1900..=2100 and `yearFrom <= yearTo`, otherwise the call returns `invalid`. `query_named` appends the filter to both the count and the page statement with the same arguments, so they filter the same set and `total` counts the filtered titles. The count compares `i.year`; the page uses `+i.year` unless the grid is sorted by year (and writes a minimum rating as `+i.rating` unless it is sorted by rating), so the sort's index answers the page in order (catalog.md). In a category the count writes `+i.year` and `+i.rating` too, so it reads the category's range, and a list of 3,000 titles or fewer sorted by another key reads its category's or its filter's range and sorts it (catalog.md, Reading).

- Year bounds compare `items.year` and are inclusive. When only one bound is set, the other defaults to its end of 1900..=2100. A NULL year fails every comparison, and a junk year (`0`, `20210`) falls outside the range, so titles without a usable year drop out as soon as one bound is set. The facets leave the same years out, so no chip can select them.
- `hideWatched` adds `i.rowid NOT IN (SELECT it.rowid FROM playback_positions p JOIN items it ON <primary key> WHERE p.episode_id = '' AND p.watched = 1)`. The subquery does not depend on the outer row, so SQLite builds the set once per statement. The set holds only watched titles, and the rowid is in every index, so a `count(*)` over 50k titles stays an index-only scan. The parental hide filter uses the same pattern for item locks.
- Migration `0013_catalog_edits.sql` adds `idx_items_year`. Migrations 0018 and 0019 rebuild it and the other sort indexes with the category, the English-only verdict, the rating and the year after the sort key, so a year range or a minimum rating on a page sorted by another key reads index entries rather than table rows. A page past the filtered total skips the page statement, so a decade with no titles does not walk the whole sort index, and a decade with only a few reads its range of `idx_items_year`.

### `catalog.yearFacets`

Args are `{sourceId, contentType: 'movie' | 'series', categoryId?, hideWatched?}`. The command returns `{year, count}[]` with the newest year first. It counts the set the grid would show:

- years inside 1900..=2100 only
- one category when `categoryId` is given; otherwise every category except hidden ones (the same `NOT IN` that `query_named` uses)
- the English-only scope, when that setting is on
- the parental hide filter, when parental controls are on in hide mode
- titles with an item-level watched row, left out when `hideWatched` is true (absent means false), using the same `i.rowid NOT IN` set that `vod_filter_sql` adds, so the counts match the grid under Hide watched

Live and radio content types return `invalid`. Stalker VOD is never stored in `items`, so a Stalker source gets an empty list.

### `positions.watchedContains`

Args are `{refs: ItemRef[]}` with 1..=500 refs; anything else returns `invalid`. It returns the refs that are watched, in input order with duplicates collapsed. It reads `playback_positions` directly and does not join the catalog, so it also answers for Stalker titles. `watched_set` gives the same answer as `ItemKey` strings for Rust callers.

## UI

### Landing

A source's Movies and Series pages (`VodLandingPage`) open with rails, the way a media library does, and keep every category one click from the top:

- A row of category chips under the header (`CategoryChips`): up to `CATEGORY_CHIP_LIMIT` (24) categories with titles in the provider's order, as links in the kit's filter-chip look (`filterChipClass`), locked ones marked. The chips scroll sideways, and the edge that hides chips fades. After them come "All categories" with the count, a quiet link with a chevron rather than a chip (first and brighter, it read as a filter that was on), and Manage categories beside it. Below md, where the shell header drops its subtitle, the row starts with the title count and All categories ends that line, while the chips take the next line across the width, ended by Manage categories (beside the two buttons a phone showed about one chip). "All categories" opens the index below, takes its heading to the top of the view and moves focus to it. Pressed while the categories are still loading, it wins over the landing's scroll memory, which then does not restore the remembered offset, and the heading is taken to the top again when the categories arrive, since their rails go in above it. The rails the jump passes mount as it lands and are a little shorter or taller than their placeholders, so for a second after the press (or until the user wheels, touches, clicks or types) a ResizeObserver on the page takes the heading back to the top whenever it drifts; it keeps 8 px under the header (`scroll-mt-2`). The press counts for the landing it was made on only: React Router keeps the page mounted when the sidebar opens another source's landing (or Series after Movies), and that landing restores its own offset.
- Rails: Continue watching for this source and section (when something was started here; each card opens its detail page, where Resume is the primary action), Recently added, Top rated (not on a Stalker portal, which sorts by name or date added only, so its "top rated" would be the newest titles), then one rail per category for the first `CATEGORY_RAIL_LIMIT` (12) categories with titles. Top rated keeps only titles with a rating and goes away with fewer than 3 (an m3u playlist rarely rates anything, so the rail was the catalog in no order), and a category that holds every title the page counts gets no rail while Recently added shows those posters already (an m3u playlist without dates has no Recently added, and keeps the category's rail). Locked categories get no rail, so their posters never show before the PIN. Each `CatalogRail` is the first page of its grid, asked with the grid's own arguments (sort, minimum rating, Hide watched), so See all opens on a cached page. A rail is a placeholder of its own height until it nears the viewport, so the page asks only for rails the user reaches; a rail whose grid is empty goes away.
- A language picker, when the provider files its categories under language or country tags ("EN | ACTION", "FR | CINÉMA"): Live's region picker (`groupRegions` in `src/features/live/lib/groupRegion.ts`, the same rule: at least two tags held by two categories each, and tagged categories half the list or more) leads the chip row and sits beside the index's filter. A pick ("FR · French · 12 categories" in the list, the language named in the app's language as the posters name it, or the bare tag when none resolves; "FR" once picked) narrows the chips, the category rails and the index to that tag's categories, followed by the untagged ones ("NETFLIX MOVIES"), which stay under every pick; All categories and the index heading count what is shown. It is kept per source and section in localStorage (`readRegion`), and a tag the provider no longer has shows every category. Its options read in the select's own width (`field-sizing: content`), so on a phone it leaves the chips their room.
- When the categories and Recently added both fail, the library itself is failing: one `ErrorState` ("Couldn't load these titles", one Try again that asks for both again) takes the place of the chips, the rails and the index, instead of the same error once per rail. Continue watching, which reads positions, stays above it. A rail that fails alone keeps its own inline error.
- Language badges: a poster in a category's rail or grid leaves out the language its category already names (`EN` and "English" on every poster of "EN | ACTION"); a title whose own prefix names another language keeps its badge, and the mixed rails (Recently added, Top rated, Continue watching) and search keep every badge.
- The full index, folded, under the rails: "Browse all categories" is a disclosure (`aria-expanded`), and whether it is open is kept in localStorage (`vod.categoryIndexOpen`). Opened from the lower half of the view (at the bottom of the page, where scrolling down to it leaves the heading), it takes the heading to the top and focuses it, as "All categories" does; higher up the page stays where it is. Open, it has a filter field and the `CategoryIndex` list, which starts with All movies or All series, and it is at least as tall as the view (the scroller's `clientHeight`, `useClientHeight`, measured while the index is folded too, so the floor is in place in the render that opens it and the heading can go to the top above a short list), so a filter that narrows the list cannot shorten the page under the view: the browser would clamp the scroll and the field being typed in would drop down the screen. Back from a category restores the scroll offset and puts focus on the category that was opened.

Typing in the header's search field opens the source's search page with the text so far, on the landing's own tab (`type=movies` or `type=series`; the page falls back to Top results when that kind has no hits, and the other tabs stay one click away). The field names what the page holds: "Search movies" or "Search series", with the source after it when there are several ("Search movies in Northwind Premium").

Category names drop a leading word that only repeats the section (`sectionlessCategoryName` in `lib/categoryName.ts`): under Movies, "Movies | Action" reads "Action" in the chips, the rail titles, the index and the grid's title, and "Series |", "TV Shows:" and "VOD -" go the same way, only when something is left. A place or language tag ("EN | ACTION 4K") moves after the name, as group and channel names draw it: the chips, rail titles, index and category picker draw `ChannelName` (the tag quiet, in the caption size), and the plain-text places, the grid's title and a detail page's "More in" rail, read "ACTION 4K (EN)" (`plainChannelName`), which is also what screen readers hear. Tooltips, search and the grid's accessible name keep the provider's name, and an index entry's tooltip gives its whole name, since the column cuts long ones.

A poster's menu (Play, or Resume for a started movie; Open details; My List; Mark as watched; `usePosterMenu`) opens from a category grid's posters, from the landing's rails (Continue watching, Recently added, Top rated, the category rails) and from Home's posters (ui-shell.md) on a right click, Shift+F10 or the context-menu key, and on a long press: a timer (`useLongPress`, as Live's rows) covers iOS, which fires no `contextmenu` on a link, and the containers turn off the link preview and text selection under a coarse pointer. Its header names the title with its poster and year, which the phone's bottom sheet otherwise covers.

The source is named only when more than one is set up (`useShowSourceName`): then the header subtitles of the landing, a category grid, a detail page and a source's search page, the landing's line below md, the movie's watch stage and the source search's placeholder and start title ("Search Northwind Premium") name it. With one source they show the count alone, the detail header has no subtitle, and a source's search reads "Search this source". A detail page's About facts always name it.

### Detail pages

A movie or series page opens on a full-width hero (`DetailHero`): the backdrop runs across the top and fades only under the text, and the poster and the title sit on its lower edge. A title with no artwork at all (none given, or every attempt failed) gets the title's tint instead of a flat page: two soft radial washes from the top edge in the poster fallback's hue (`heroWash`, `hueOf` of the same title), pale in the light theme and deep in the dark one, under the same fades, so the text keeps its contrast. Under the title come the meta line, the action row, the resume bar with its time left, and the plot. The action row has two groups, so a narrow column wraps between them and never inside one: the text buttons (`actions`: one primary, Play or Resume, and Trailer when there is one), then the icon buttons (`icons`, a `HeroIconGroup` of `HeroIcon`s), in the text buttons' rounded square so the row has one shape, as on Home's hero: Start over when there is a saved spot (for a series, of the episode Resume points at), My List, Favorite, Watched, Download for a movie, and a More menu only for what is left (Other sources, Stream instead, the parental lock). My List is the one labelled button among them (the bookmark and "My List"), so it is not one of two look-alike save glyphs beside Favorite's heart. Each round button has a short caption under it on every width (Restart, Favorite, Watched, Download, More; `HeroIcon`), so every action in the row is named in words, as Play and My List are; the button keeps its full name and tooltip. Favorite is a pressed toggle with the heart filled in, so the page says whether the title is a favourite. A watched title also says "Watched" in the meta line; the container format stays in About, not the meta line. A finished download whose file is there plays from the file, and the line under the actions says so. Titles over 40 characters take the headline size instead of the display size and stop at three lines. Below 640 px the primary takes the whole width, the resume bar sits right under it, and the icons become a row of equal tiles across the width, My List among them as a square over its caption; there the backdrop's fade starts at the top and the leading-edge fade is off, so the muted meta line and resume caption keep 4.5:1 on any art. While the title loads, the skeleton keeps the artwork's room except for an M3U title without a cached backdrop, so the page does not jump as it lands. A title the provider no longer lists (`not_found`) gets an empty state with Browse movies (or series) and, when My List, Continue watching or Recently watched remembers its name, Search for it, instead of an error. The catalogue pages and My Videos' detail page, which reuses the same hero, put Back in the shell header (ui-shell.md); the hero draws none of its own.

An Xtream title opened from a grid, a rail, Recently added or search shows its hero from the catalog row that list holds while the provider answers (VOD-DETAIL-PLACEHOLDER, [performance.md](performance.md#vod-landing-and-detail-pages)): title, poster, year, rating and format at once, the plot, backdrop, cast, runtime and genres when the answer lands. A movie's Play works from the first frame; a series shows Play and its Watched button disabled and placeholder episode rows until its seasons arrive (marking the series marks every episode, and the episodes come with the seasons). A title no list holds (a cold link, My List), an m3u title and a Stalker title show the skeleton as before.

Play switches the page to its watch view (`WatchStage`): the player at full content width, under a slim bar with the title, the source (or the playing episode) and a close button; Escape closes it too. The player leaves out its own title bar there, and the shell header names the section (Movies or Series) instead of repeating the title; the window and tab keep the title through the header's `documentTitle` (ui-shell.md). The header keeps its Back: it leaves the page and playback carries on in the mini player, as the browser's Back does, while the close button stops it. At xl a series' Up next rail sits beside the player in a column as tall as the player and scrolls inside it, so the player keeps its 16:9 box. Under the player is the hero's own icon set (`HeroIconGroup`), so the two states share one look: square icon buttons, a pressed toggle drawn as a filled glyph, other sources and the lock in More. A series page puts Previous episode first in that row.

### Search: Top results

When a search finds more than one kind of result, the search page opens on Top results (`TopResults` in `SearchPage.tsx`) instead of the first kind's tab: a section for each kind it found, each with up to 12 posters, 6 channels or 5 programmes and a See all that opens its tab. The sections come in order of how many results each has (a tie keeps movies, series, channels), with programmes last, so the kind the query mostly found leads, on a phone too. In a search across several sources, posters fold the same title from different sources into one card that says how many sources have it; the per-type tabs list every copy with its source badge. A section heading counts what its tab counts, every copy, and the "2 sources" chip explains a card that stands for two. When movies and series each hold three titles or fewer, they share one "Movies and series" rail (with no See all, since no single tab holds both) instead of two short rails. With one kind of result the page shows that kind's tab, as before. Top results' poster rails and the start screen's Jump back in open the posters' menu (`usePosterMenu`: Play or Resume, Open details, My List, Mark as watched) on a right click, Shift+F10, the menu key or a long press, as the Movies rails do; each title plays with its own source's kind (`PosterMenuItem.sourceKind`), since one menu serves every source. Programme rows (`ProgrammeList`, in Top results and the Programmes tab) fold a show airing on several channels at once (the same title and start) into one row: the title opens the guide at the first channel's programme, and each other channel is a small link on the line under it that opens the guide at its own (the first 8; the rest behind a Show all toggle, which counts every channel, the title's too, as the palette's row does, so one show cannot fill the page), so "Inside the NBA" at 9:00 on six channels takes one row instead of six, and Top results' five rows are five shows. Every wrapped line of links starts under the channel name above, and under a coarse pointer each link and the toggle take `TOUCH_TARGET`. Back from the guide to a channel that was behind Show all opens its row again (the opened rows are kept per history entry), so focus can land on its link. A programme on the air has a LIVE pill beside its title, so its row is as tall as the others. The rows keep each hit's place in the whole list (`data-grid-index`), which focus and Back's return go by, and Up and Down step through the rows and the channel links.

### Search: names, waiting and empty answers

The search of every source is "Search everything" in its field and its start title, the name the header's box has on every other page, and the header shows no palette button beside it (`hidePalette`; Ctrl+K still opens the palette). Its start screen's Jump back in posters carry the user's own progress, as the landings' do. With no source set up the page is the shared no-source state (`NoSourcesState`, Add a source and Import a backup).

While the results on screen answer an older query than the field holds and do not narrow to it (a word replaced or shortened), they are dimmed (`opacity-70`, `aria-busy`) until the answer comes, as the guide's search panel does; while the first query of a visit runs, the skeleton shows instead of the start screen. A query that is a channel number (1 to 5 digits) also finds the channel at that number in each searched source (`useChannelNumberHits`, `withNumberHits`), first among the channels. Channel results, on the page and in the palette, leave out a provider's heading rows ("####### ESPN+ #######", `isSeparatorName`) and put the channels of the user's region first (the region picked in the source's Live TV groups, else the browser language's; a channel's region is the place tag on its name, else its group's), then those whose name holds every typed word whole ("ESPN HD" before "ESPN2" for "espn"), the core's order otherwise (`rankChannels` in `lib/search.ts`). The core ranks and caps the list first, so on a big playlist this orders the first page only; ranking every match needs `catalog.search` itself. Programmes are asked 200 per source (the most `epg.search` allows), and the Programmes tab and section count shows (rows after folding), with "+" when the answer reached that limit. When a source's guide search fails (`useProgrammeSearch` returns `error` and `retry`), the Programmes tab stays, without a count when nothing came back, and the tab, its Top results section and the no-results state say "Couldn't search the TV guide" with Try again (`ProgrammeSearchError`), instead of dropping the programmes as if nothing were on. A source's search that finds nothing offers "Search everything for "…"" (`SearchEverythingLink` in `src/shell/SearchEverythingLink.tsx`; Live TV's channel search outside a group, a category grid's search, the guide's search panel and Sports' team search offer it in their empty states too), and the no-results hint says that search matches the start of words. The search of everything also lists the settings whose names or keywords match (`useSettingMatches`, `SettingsMatches`, ui-shell.md), under the results; when only settings match they lead, with the no-results note as a quiet line under them.

A channel result names what is on now under the channel's name (one `epg.nowNext` call for the first 60 hits, `useNowTitles`, and for Top results' six), which is how "ESPN HD" and "ESPN (Backup)" are told apart, and right click, Shift+F10 or the context-menu key opens Home's channel menu (Live TV's: Play, Open in TV guide, the favourite heart, Add to multi-view, Add to list, the channel edits and the parental locks, headed by the channel; `ChannelMenuHost` around the page).

### Search: typing

The field's text is the page's `draft` (`useUrlSearchDraft`), and the query goes into the URL 100 ms after the last key (`DEBOUNCE_MS`). Every write the hook made that the URL has not shown yet counts as its own, not only the last one: the router commits a write as a transition that keys keep interrupting, and on a slow machine an older write could land after a newer one was made, which the hook took for an outside move and put back in the field, dropping the letter typed in between (3 of 6 runs of the test below ended with "dark rver"; `searchDraftLate.test.tsx`).

While the field holds a longer query than the one the results on screen answer, the results narrow to it on the client at once (`previewGroups`) and the new answer replaces them when it comes. A key's own render only echoes the key in the field: the narrowing reads the draft through `useDeferredValue`, so it follows as a deferred render that the next key interrupts, and Top results (`TopResults`, memoized, with a stable `typeHref`) renders again only when the results it shows change. Typing "dark river" at about 8 keys a second into a search of a 164,000-title catalog at a 4x CPU slowdown (Playwright and Chromium; medians of 5 and 4 runs), each key's input handler ran 58 ms before and 20 ms after (LoAF script timings of `oninput`), and the keydown's event duration at the 75th percentile went from 112 to 84 ms. `searchKeystroke.test.tsx` checks that a key that leaves the results as they are renders no Top results rail, and that narrowing still comes before the answer.

The answer itself renders in a transition (NAV-3). TanStack Query hands a reader its query's changes through `useSyncExternalStore`, which React always renders synchronously, so a `catalog.search` answer rendered the whole page in one task inside the query's notify timer. The page's two `catalog.search` reads pass `transition: true` to `useRpcQuery`, which reads through `useTransitionQuery` (`src/api/query.ts`). That hook keeps its own `QueryObserver`, as `useQuery` does, and re-renders the reader inside `startTransition` when the observer reports a change; the observer reports only changes to the result fields the reader's renders read, so a fetch that starts, or a refetch that brings the same data, re-renders a reader of `data` not at all. (Until round three it listened to the whole query cache from every transition reader and re-rendered on every change to its query, a fetch starting included; the search numbers below held with the new hook: one search change took 463 against 481 ms to its results, 45 against 52 ms of blocking time and 726 against 679 ms of main-thread time, medians of 9 interleaved runs.) React then renders the results in slices between which the browser paints, and keeps the old results on screen until the new ones are complete. Changing a search with one input event ("dark" to "dark river" and three more pairs, 164,000 titles, 4x CPU slowdown, medians of 8 interleaved runs each), the longest task after the input went from 109 to 84 ms, the longest notify-timer script from 96 to 63 ms, and total blocking time from 166 to 47 ms; main-thread time stayed the same (714 against 690 ms). The other long tasks left there are other queries' answers (the programme search, the resume and lock lookups) and the page's first keystroke. `src/api/transitionQuery.test.tsx` covers the hook. The detail pages' provider query was tried the same way and measured no clear gain on a cold open (the open is dominated by the boot), so they still read through `useQuery`. So was the Movies landing (round three: every rail's page and lookups under `TransitionReads`): going from Home to Movies, blocking time went from 94 to 124 ms, the longest task from 92 to 127 ms and main-thread time up 10 %, with the rails on screen no sooner (8 interleaved runs each, 4x CPU slowdown). The landing's answers come in a dozen at once, and React renders the pending transitions together, so the first rail waited for the others; the landing keeps its synchronous readers.

### Filter row

`VodFilterBar` (`DecadeChips`, `YearRangeFields`) on every Movies and Series grid. The decade chips sit in the grid's toolbar beside the search and the sort; the exact range and Hide watched are in a panel under it that the toolbar's Filters button opens, whose badge counts the filters that are on. Where the row has no room for every chip beside the controls and the whole search placeholder (`useToolbarFit` measures the chips, the other controls and the placeholder in the page's language; a real library's eight decades with counts need it at 1440 px beside the rail) the chips take their own line under the controls and the search grows to fill the row. The search field's Ctrl F key caps show only while the placeholder still fits beside them, so they are the first thing to go when room is short. Below 640 px the sort and the chips fold into that panel too, so the grid starts right under the search row. The toolbar's search says its scope ("Search this category", or "Search all movies" on All movies), since the header's field beside it searches everything. Over an empty result the header leaves the count out.

- Category picker. Categories, after Back, opens the source's categories in a dialog (a sheet on a phone) with a filter, the current one marked, and All movies or All series with the titles' count; the list is as tall as its rows, up to 480 px. With a mouse the filter takes focus; on touch the list does, so the keyboard does not cover it. A pick replaces the grid in history, so Back and Escape still return to the landing.
- Decade chips. For m3u and Xtream sources the chips come from `catalog.yearFacets`, summed per decade. Each chip has a thin level bar showing its share of the busiest decade, and its accessible name includes the count ("1990s, 8 titles"). Stalker portals cannot report years up front, so they get fixed chips from the 1950s to the 2020s without counts. If the facet call fails, the row falls back to those fixed chips. While facets load, the row shows skeleton pills. When a catalog has no years at all and no range is set, the chip group is hidden. Clicking the active chip clears it. All years keeps the resting chip look while no range is set (pressed for assistive tech only): inverted and first, it read as a filter that was on. With Hide watched on, the facet call adds `hideWatched: true`, so the counts and level bars describe the titles the grid keeps; flipping the switch keeps the current chips until the new counts arrive.
- Exact range. Two selects, From and To. Their first option ("From" or "To") means no bound. A reversed pick is swapped. When the range covers exactly one decade, that decade's chip shows as pressed.
- Hide watched. A switch at the end of the panel. It writes `settings.vodHideWatched` through the optimistic `useUpdateSettings`, so the choice holds across grids and restarts.

On a phone the chips scroll sideways inside their own row, so the page never scrolls horizontally. The row uses logical properties (`ms-auto`, `start`/`end`), and its transitions sit behind `motion-safe:`. The chips are the kit's `FilterChip`, as are the rating floor chip and the search page's source facets.

A category with fewer than 12 titles (`FEW_TITLES` in `CategoryGridPage.tsx`, counted from the category's `itemCount`, so the toolbar does not change as filters narrow the grid) (All movies and All series count the shown categories' titles) has no decade chips and no search field of its own: for a row of posters they were most of the page. Either comes back while it is in use (a decade from the URL, typed text), so it can be cleared.

### URL

The range lives in the URL as `yf` and `yt` (both inclusive), so a filtered grid can be linked, reloaded and restored with Back. `readGridParams` reads them through `readYearRange`. Values that are not four-digit years in 1900..2100 are ignored, and a reversed pair is swapped, so a hand-edited link never reaches the core as an invalid call. Both VirtualGrids are keyed on the category only, so a filter change keeps the grid mounted: each page shows its old titles until the new page answers (`sameGridSlot` in `useVodPage`), and the old posters dim to 60 % once the wait passes 150 ms (`aria-busy` on the grid's wrapper). A new sort, search, rating, English-only state or year range (`filterKey`) scrolls the grid to the top and, through VirtualGrid's `resetKey`, puts the keyboard cursor on the first title (or clears it when the grid has no keyboard focus). Hide watched is not part of that key, so flipping it keeps the scroll position and the cursor.

### Paging

`buildPageRequest` sends `yearFrom`, `yearTo` and `hideWatched` only to `catalog.*`. Stalker pages come straight from the portal, so a year range or Hide watched switches a Stalker grid to the in-order loader (`useVodPagesInOrder`), the same one the rating and English-only filters use. The grid filters the loaded pages with `filterByYear` (the same 1900..2100 rule as the core) and the watched set. With Hide watched on, a page is shown only once its watched lookup has answered, so watched titles never flash in and then disappear. The filtered count is final once every page has loaded. A Stalker `CatalogRail` (the landing's category rails, "More in" on a detail page) does the same on its one page: with Hide watched it waits for the page's watched lookup, drops the watched titles and only then takes its 20.

Rows are sized for a two-line title and the year (`GRID_CAPTION_HEIGHT`, 62 px at 100 %), so a wrapped title keeps its year inside the cell. The loading grid (`SkeletonGrid` with `captionHeight`) gives its cards the same caption height and the grid's 16 px gap, so its rows sit where the posters' will. The space above the first row is inside the scroller (VirtualGrid's `paddingStart`), so the first row's hover lift and focus glow are not cut and scrolled posters run up to the toolbar's rule. The keyboard cursor's ring on the card is the grid's only focus mark; the listbox draws its own only while it has focus and no cursor.

On SQLite grids each cell reads its own page, through the grid's page gate (`pageGate.ts`): a scrollbar drag fetches the pages it rests on, not every page it passes (see performance.md, "Long lists and grids").

### Watched tick

Each loaded page asks `positions.watchedContains` once (`useWatchedKeys`, `useWatchedPages`), and the cells of that page share the query. A watched poster shows a check in the top-end corner, beside the rating chip, and its accessible name ends with "Watched". A watched title does not show a resume bar. If the lookup fails, nothing is ticked.

`useSetWatched` and the grid's Undo call `invalidateWatched`, which refreshes `positions.*`, `userstate.*`, and the `catalog.movies` / `catalog.series` pages and `catalog.yearFacets` counts fetched with `hideWatched`, so a newly watched title leaves a filtered grid right away.

### Keys (area Vod)

| Key | Action | Description key |
| --- | --- | --- |
| `w` | Marks the title under the grid cursor watched, or unwatched if it already is. It asks the core first, so it never acts on a stale tick. A toast confirms and offers Undo. | `vod:shortcutWatched` |
| `shift+w` | Turns Hide watched on or off. | `vod:shortcutHideWatched` |

`w` is also bound in the My List area. The bindings are scoped to their pages, so they do not clash.

### Empty states

When the grid comes back empty, the reason is checked in this order: the rating minimum, then the year range ("No titles from these years", with an "All years" button), then Hide watched ("You have watched everything here", with "Show watched"), then search, then an empty category.

### Series detail

The hero's primary names its episode in words, "Play season 1, episode 2" or "Resume season 1, episode 2" (`playEpisode` / `resumeEpisode`), or "Play episode 2" when the series has one season or the episode is a special (`playEpisodeNumber` / `resumeEpisodeNumber`); More's "play from the first episode" does the same. The hero actions include a series-level `WatchedButton` (labels `markSeriesWatched` / `markSeriesUnwatched`). It writes the item-level row, and the page reads it back from `positions.forSeries`. The season button is separate and still marks episodes. Each episode row has its own watched button beside Download (one press, named for what it does, "Mark S01E02 as watched" or "as unwatched", with the tick green once watched), in place of a More menu that held only that action. The download control keeps one width in every state, so the watched ticks stay in a column: a finished download is the file-on-disk glyph (not a second green tick), a queued one a clock, a paused one a paused circle, and only a running one spins with its percent. The episode Play or Resume starts is marked "Up next" at the start of its facts while nothing plays. A watched row says so with the thumbnail's tick and the green toggle, not a third time in words. Titles that are only the show's name and the code ("Show S01E02") read "Episode 2". An episode without a still (normal for M3U and many Xtream providers) gets a quiet tile (`bg-surface-2` with the edge) with its number ("E2") instead of initials tinted from its title, which made a season a column of colours. Past eight seasons the season tabs become a dropdown ("Season 2 · 10 episodes"), since a mouse wheel cannot scroll the tab strip. On a phone, and under the player, the season's actions (Download season, Mark season watched) are one menu named for the season. Next to it, Download season queues every episode of the selected season that has no download yet, or only a failed, cancelled or missing one (downloads.md). On a phone (below sm) an episode row is one 84 px line: the thumbnail, the facts over a two-line title, then the watched and download buttons. The facts keep to one line there, the code, the runtime, Now playing and the downloaded icon, and an item that does not fit (Now playing beside a long runtime) is left off whole rather than cut. Watched and the percent are left to the thumbnail's tick and bar and to the play button's name, which says both at every width.

### Preferred source

A movie that other sources carry too (`catalog.sameTitle`) has an Other sources dialog, where one copy can be pinned so Play uses it. Pins are kept by the core in `vod_source_pins`, one per title match key (`matchKey` in `src/features/vod/lib/pins.ts`: the normalized title base plus the year), through `sourcePins.get`, `sourcePins.set` and `sourcePins.clear` (`useSourcePin`). Backups export and import the table (backup.md). Builds before these commands kept pins in localStorage (`vod.sourcePins.v1`); the first pin read of a page load moves them into the core (`migrateLocalPins`): a key the core already has keeps its pin, a pin whose source is gone is dropped, and the local copy is deleted once nothing is left to retry.

### Recent searches

The search page's zero state offers the last 8 queries the user acted on (`lib/recentSearches.ts`, localStorage `vod.recentSearches`): a query counts once it was submitted with Enter, a result was opened from it, or its chip was picked. While parental controls are set (a PIN), nothing is remembered and nothing is offered, and setting them clears the list. The core filters what Hide mode hides from every list, but these chips are the UI's own, so a parent's query for a locked title would otherwise wait there for the next person once the unlock ran out (parental.md). The chips show only once the parental status says controls are off: not on a cold start before it is known, so a stored chip never flashes up, and not when it fails to load. Clear history on Recently watched, for every source, clears them too, and its Undo brings them back. Tabs share the list: another tab's write or clear reaches this one through the `storage` event, and each change starts from what is stored, so a tab never writes back queries another one cleared.

### "More like this" lookups

"More like this" (`SimilarSection`) and an actor's Known for match TMDB's titles against the catalog with one `catalog.search` each (`useCatalogMatches`, up to 20 per list). The section sits below the fold, so its lookups wait until it nears the view (`useNearViewport` on the page's scroller) and the page is idle (`whenIdle`), as Home's trending rail does, instead of queueing beside the page's own reads. A Stalker portal's VOD is not in the local catalog, so nothing could match there: neither page asks.

## Bundle budget

English `vod.json` is bundled into the entry chunk, and the C4 strings add 422 bytes to it (minified JSON). The filter row, hooks and series button load with the VOD route chunk.

Pages that draw no player load it on the press, as Home does (performance audit SH-2): Search plays a channel and a category grid's poster menu plays a movie through `import('@/features/player')` (`usePlayTitle` for the grids). A static import of the player barrel for `playItem` made those routes wait for the player's controls chunk before their first render. The detail pages, which show the player, keep `usePlayback`. `pnpm size:check` fails when the Search or category grid route chunk statically loads the player's UI (performance.md).
